# 윤곽 보존·약한 선명화 추가 기록

## 반영 내용

버전 1.2.0 / 릴리스 2026-10-21.3에서 두 옵션을 데스크톱과 CLI에 연결했습니다. 조합은 기본, 윤곽 보존, 기본+선명화 0.2, 윤곽 보존+선명화 0.2입니다. 업로드 안내 문구는 `클릭해 이미지를 첨부하세요.`로 변경했습니다.

`detail_restore.py`의 `DETAIL_RESTORE_POLICY`에서 기본값과 알고리즘 상수를 관리합니다. `restore_image_detail()`은 재생성 결과와 원본을 받아 복원·윤곽 혼합·선명화·최종 정수 변환을 순서대로 수행합니다. `_detail_edge_weights()`는 전체 이미지 기준 99백분위로 윤곽 가중치를 정규화합니다. 나머지 연산은 주변부를 포함하는 행 단위로 처리해 큰 RGB 실수 배열의 중복 생성을 피합니다. 색상 프로필·투명도·출력 확정은 기존 Qwen 처리 흐름이 담당합니다.

설정은 UI → 별도 작업 프로세스 → Qwen → 디테일 복원으로 전달됩니다. UI에서 옵션을 변경해도 기존 결과는 즉시 삭제하지 않으며 사용자가 `적용 후 처리`를 선택해야 다시 처리합니다. 작업 중 옵션 변경을 막고, 취소 요청을 각 행 묶음에서 확인합니다. 추가 외부 통신이나 의존성은 없습니다.

## 설정·이슈·커뮤니티 조사

2026-10-21 확인한 자료와 반영 기준입니다. 외부 보고는 작성자의 주장과 실험이며 이 프로젝트에서 직접 재현한 검출 결과와 구별합니다.

- [DeSynth 고정 리비전](https://github.com/0xROOTPLS/DeSynth/tree/0c2b14fa6b92fff3721877838fcb9de78fdec0ff): Q4, 8단계, 강도 0.25, 복원 폭 1.95는 기존에 반영했습니다. 이번에는 원본의 `edge` 모드와 선명화 권장값 0.2를 추가했습니다. 기본값은 Gaussian과 선명화 0입니다.
- [DeSynth PR #1](https://github.com/0xROOTPLS/DeSynth/pull/1): 조회된 이슈 목록은 Apple Silicon 호환 PR 한 건이며, 추가 성능 피드백은 확인하지 못했습니다. 병합된 실제 코드의 장치·자료형 처리를 우선했습니다. 메모리 상한 해제와 검증 없는 파일 로딩은 도입하지 않았습니다.
- [remove-ai-watermarks 연구 기록](https://github.com/wiltodelta/remove-ai-watermarks/blob/main/docs/synthid-removal-research.md): 작성자는 공개 DeSynth의 원본·기본 출력·윤곽 출력 모두 현행 OpenAI 검사에서 검출됐다고 보고합니다. 옵션 이름만으로 제거 성공을 단정하지 않고 동일 입력·시드·검사 서비스로 비교할 근거로 삼았습니다.
- [froggeric 구현](https://github.com/froggeric/gemini-watermark-and-synthid-remover): SDXL 재생성과 디테일 복원의 밝기별 차이를 보고합니다. 다른 모델의 강도 0.08~0.10을 Qwen Lightning에 그대로 복사하지 않았습니다. 복원 영향을 분리해 확인할 수 있는 기존 `--no-restore`를 유지합니다.
- [Reddit 작성자 실험](https://www.reddit.com/r/comfyui/comments/1q2z02m/update_i_figured_out_how_to_completely_bypass/)과 [Hacker News 경험담](https://news.ycombinator.com/item?id=49797343): 확산 재처리 성공 주장과 심한 화질 손상 없이는 검출이 남았다는 경험이 함께 존재합니다. 통제된 공통 샘플·설정·판정이 없어 숫자 설정으로 자동 반영하지 않았습니다.

초기 기능인 메타데이터 정리, 등록된 가시 표식 처리, 재생성은 기존 단일 처리 흐름에서 함께 실행됩니다. 별도의 미세 픽셀 처리를 무조건 추가하거나 여러 번 재생성하지는 않습니다. 이 조합의 개선 근거가 없으며 재생성으로 일반 AI 탐지 점수가 오히려 오른 샘플도 있기 때문입니다. 공개 워터마크 검사와 로컬 주파수 통계는 SynthID 판정을 대신하지 않습니다.

## 실제 두 샘플의 비교

기존 시드 42의 Q4 재생성 중 저장해 둔 복원 전 결과를 사용했습니다. 이 파일로 기본 복원을 다시 계산했을 때 이전 Q4 출력과 픽셀이 완전히 같음을 먼저 확인했습니다. 따라서 모델을 새로 실행하면서 발생하는 변동 없이 복원 옵션만 비교했습니다.

| 모드 | 샘플 A PSNR | 샘플 B PSNR |
| --- | --- | --- |
| 기본 | 26.89 dB | 27.05 dB |
| 윤곽 보존 | 25.83 dB | 25.97 dB |
| 약한 선명화 0.2 | 26.89 dB | 26.96 dB |
| 윤곽 보존 + 약한 선명화 0.2 | 25.88 dB | 25.97 dB |

새 비교본 6개는 각각 DeSynth의 해당 복원 수식으로 전체 이미지를 계산한 결과와 픽셀이 일치했습니다. 원본 파일 해시·출력 크기·색상 프로필을 확인했습니다. PSNR은 원본과의 픽셀 차이입니다. 윤곽 모드의 PSNR은 기본보다 낮으므로 원본 보존이 수치상 개선됐다고 설명하지 마십시오.

사용자의 새 비교본 6개 전송 동의를 받은 뒤 외부 검사를 진행했습니다.

| 샘플 / 옵션 | Sightengine GenAI | 주요 생성 모델 추정 |
| --- | --- | --- |
| A / 윤곽 보존 | 99% | GPT 75%, Qwen 17% |
| A / 약한 선명화 | 99% | GPT 91%, Qwen 6% |
| A / 결합 | 99% | GPT 72%, Qwen 21% |
| B / 윤곽 보존 | 99% | Qwen 69%, Wan 22% |
| B / 약한 선명화 | 99% | Qwen 58%, Wan 28% |
| B / 결합 | 99% | Qwen 71%, Wan 22% |

Sightengine은 6개 모두 정상 완료했고 일반 AI 판정은 감소하지 않았습니다. 이 수치는 화면의 정수 표시이며 생성 모델 추정은 실제 사용 도구의 증명이 아닙니다. SynthID 해독 결과로 해석하지 마십시오.

OpenAI Verify는 첫 A 윤곽 보존본에서 `문제가 발생했습니다. 다시 시도해 주세요.`를, Google은 같은 파일에서 `Something went wrong! Please wait and try again later`를 반환했습니다. 각 서비스에 한 번씩 업로드한 후 반복 요청을 중단했습니다. 나머지 각 5개는 미시도이며 공식 검출 음성으로 계산하지 않습니다. 앱 처리 보고서의 SynthID 상태는 여전히 `not_tested`입니다. 이전 기본 Q4의 공식 판정은 [기존 검증 기록](REPAIR-2026-10-21.md)을 참고하십시오. Gemini 양성 샘플 부재도 그대로 남아 있습니다.

파일 해시와 서비스별 결과·오류 화면은 로컬 결과 폴더의 `external-comparison.json`과 이미지·텍스트 증거에 보관합니다.

로컬 비교 이미지와 해시·수치 보고서는 Git에서 제외된 `local-results/2026-10-21/detail-options/`에 보관합니다.

## 검증 범위

Python 회귀검사 171개 및 하위 검사 151개가 통과했습니다. 새로운 검사는 128행 처리와 전체 이미지 처리의 일치, 작은 이미지·평탄 이미지, 원본 불변, 취소, 옵션 범위, 실제 출력까지의 옵션 전달과 투명도·색상 프로필 보존을 포함합니다. 작은 가짜 모델을 이용한 회귀검사와 실제 샘플의 복원 계산을 구분합니다. 실제 워터마크 제거 성능을 이 검사 수로 표현하지 마십시오.

macOS 1.2.0 앱의 패키징, 소스 및 패키지 내부의 작은 실제 엔진 검사, 소스 해시 일치 검사가 통과했습니다. 이전 1.1.0 앱은 프로젝트 밖 보관 폴더로 옮겼습니다.

네이티브 앱의 1.2.0 시작과 변경된 첨부 안내를 화면에서 확인했고, 패키지 CLI에서 새 옵션이 노출됨을 확인했습니다. 데스크톱 자동화 도구가 창 좌표를 찾지 못해 옵션 대화상자의 마우스 조작은 확인하지 못했습니다. UI의 옵션 전달 및 처리 결과는 오프라인 검사로 검증했습니다.
